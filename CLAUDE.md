# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Kitsune" — a full-stack Bun app with zero runtime dependencies — the server framework AND the browser JS (`public/kit.js`, an `hx-*`-compatible client: requests/swap/oob/boost/preload/SSE/WS) are written in-house (no Elysia/Express/React): `core/server.ts` (router + pipeline on `Bun.serve`), `core/schema.ts` (validation), `core/jsx/` (JSX → strings), `core/cookie.ts`, `core/openapi.ts`. Don't reintroduce third-party server/JSX/validation/htmx libraries. Backend and frontend live in one process. README, comments and UI copy are mostly in Thai; match that when editing user-facing text and existing comments.

## Commands

Runtime is Bun (not Node).

```bash
bun install
bun dev                  # bun --watch index.tsx (http://localhost:3000)
bun start                # NODE_ENV=production
bun run start:cluster    # multi-process on one port (Linux only; uses REUSE_PORT/WORKERS)
bun test                 # all tests
bun test tests/cache.test.ts            # single file
bun test -t "name pattern"              # single test by name
bun run check            # scripts/check-routes.ts (also regenerates core/routes.gen.ts) && tsc --noEmit && scripts/xss-scan.ts
bun run bench            # CLI load test against a running server
bun run trailer          # builds dist/kitsune-trailer.mp4 (three.js + puppeteer + mp4-muxer; see trailer/)
```

Env vars (PORT, DB_FILE, ADMIN_KEY=dev-secret, COOKIE_SECRET, CACHE_MAX_MB, WORKERS, LOG, LOG_STATIC, LOG_BENCH) are documented in README.md.

## Architecture

**`index.tsx`** only listens and prints the banner. **`core/app.ts` `createApp()`** builds the whole `App` (plugins, Server-Timing, global `onError`, route loading, OpenAPI docs); tests call it and use `app.handle()` without opening a port. `tests/setup.ts` (preloaded via `bunfig.toml`) sets `DB_FILE=:memory:` and `NODE_ENV=test` (which also disables request logging).

**File-based routing (`core/router.ts`)** — `src/api/**` (prefix `/api`) and `src/pages/**` are scanned and registered:
- `[id]` → `:id`, `[...slug]` → `*`, `(group)` folders vanish from the URL, `index` is dropped. Static routes are sorted before dynamic, wildcard last.
- Any file/folder starting with `_` is not a route (`_guard.ts`, `_404.tsx`, …).
- Exports named `GET/POST/...` are handlers; in pages `export default` is GET. A handler is either a plain function or `defineRoute({ body, query, params, headers, handler, beforeHandle })` from `@core/route` (gives typed context). `export const WS = defineSocket(...)` registers a WebSocket at the file's path (prefer a separate file from GET).
- `export const cache = <seconds>` caches the GET response (`core/http-cache.ts`: brotli/gzip precompressed, ETag, `X-Cache`). Never use on user/cookie-dependent pages.
- `_guard.ts` (default export `Guard` with `derive`/`beforeHandle`) applies to its folder and all subfolders, running before the route's own `beforeHandle`; `derive` results are merged into the context.
- **Next.js-style page composition (pages only, GET only):** `composePage()` in the router chains `export const loader` (result → `ctx.data`; returning a `Response` short-circuits; `notFound()` from `@core/route` → 404) → `metadata` / `generateMetadata` (merged outer `_layout` → inner → page into `ctx.metadata`) → page handler → nested `_layout.tsx` files wrapped inner→outer. Layouts receive `{ children, metadata, ctx }`. A result that is already a full document (`<html`/`<!doctype`) stops further wrapping, which is why legacy pages that call `<Layout>` themselves keep working. The root layout is `src/pages/_layout.tsx` and wraps every page GET that returns a fragment, so **GET routes that return fragments/files (`examples/htmx/*`, `cache/{keys,slow,stats}`, `benchmark/live`, `trailer/bundle`) must `export const layout = false`**. Pages set `title`/`path`/`wide` via `export const metadata`/`generateMetadata` and return fragments (`<Example>` is a fragment component too; `examples/_layout.tsx` only adds `path: '/examples'` for nav highlighting). `users/[id]` uses `loader` + `notFound()`. `export const layout = false` opts a page out.
  - `_not-found.tsx` / `_error.tsx` / `_loading.tsx` (nearest folder wins; boundaries are wrapped by layouts). `export const stream = true` renders via our `renderToStream` (`core/jsx/suspense.ts`): layouts are rendered around a marker, split, and the page stream is sandwiched in; the page receives `ctx.rid` and `ctx.loading` for `<Suspense>`.
  - Browser side is `public/kit.js` (loaded by `Layout` via `asset()`); it keeps htmx's `hx-*`/`sse-*`/`ws-*` vocabulary and `htmx:*` event names. `App.finalize` rewrites `3xx + HX-Redirect` to `200 + HX-Redirect` for requests carrying `HX-Request`, because fetch follows redirects invisibly. Pages exporting `cacheTags` get `max-age=0, must-revalidate`. kit.js has no unit tests — verify changes in the browser (`preview_start kitsune-dev`).
  - `export const actions = { name: defineRoute(...) }` registers `POST <path>/_/<name>` (see `actionUrl`); `redirect()` sets both `Location` and `HX-Redirect`.
- **Response cache** (`core/http-cache.ts`): `export const cache`, `swr` (stale-while-revalidate, `X-Cache: STALE`), `cacheTags`; `revalidatePath/Tag` (re-exported from `@core/route`). Optional SQLite L2 (`core/cache-store.ts`, `CACHE_STORE=sqlite`) shares entries across cluster workers; L1 is capped at `CACHE_L1_SECONDS` so invalidation propagates. `bun run check` fails on cached routes under a `_guard`.
- **Request pipeline additions in `createApp()`:** `src/middleware.ts` (`core/middleware.ts`, runs in `onRequest`, Next-style `matcher`), `sessionPlugin` (`core/session.ts`, `ctx.session`, SQLite-backed, signed `sid` cookie), dev-only error overlay (`core/dev-overlay.ts`), dev-only hot reload (`core/hmr.ts`: SSE `/__dev/hmr`, `core/dev.ts` watches `public/`, Layout injects `HMR_SCRIPT`), and `core/security.ts` (security headers + 403 for cross-origin unsafe methods; requests without Origin/Sec-Fetch-Site pass so curl/tests work).
- **`href()`** (`core/href.ts`) is type-checked against `core/routes.gen.ts`, which `createApp()` regenerates (non-production). If `tsc` complains about a valid new route, run the app/`bun scripts/check-routes.ts` once to regenerate it — `bun run check` does this first.
- Loaded routes are recorded in the exported `registry`.

**Components** — `core/components.ts` scans `src/components/**/*.tsx` (PascalCase, `export default`) and **auto-generates `src/components/index.ts`**; import via `@components`. Don't hand-edit that index. Path aliases: `@core/*`, `@components`.

**Dev reload (`core/dev.ts`)** — `bun --watch` doesn't notice added/removed files, so a `fs.watch` on `src/` regenerates components and rewrites `core/reload.gen.ts` (gitignored, imported by index) to trigger a restart. Adding a route or component in dev should just work.

**Errors (`core/app.ts` `onError`)** — responses differ by path: `/api/*` returns JSON, pages return HTML (404 renders `src/pages/_404`; validation errors return 422 with an HTML alert fragment for htmx). A tampered signed `session` cookie is cleared and redirected.

**Other core pieces** — `core/cache.ts` (Redis-like in-memory LRU+TTL, `remember()` is stampede-safe), `core/static.ts` (serves `/public` from memory — fonts live in `public/fonts` with `@font-face` at the top of `style.css`; no CDN anywhere, precompressed; use `asset()` from `src/lib/asset.ts` for `?v=` cache-busting URLs), `core/logger.ts` (banner, route table, request log). `src/lib/db.ts` is bun:sqlite (WAL) with seeded users + 10,000 products. `src/lib/examples.ts` lists the example pages shown on `/` and `/examples`.

**`trailer/` and `scripts/trailer.ts`** are an unrelated-to-the-app promo video pipeline (three.js scenes rendered via puppeteer); `src/pages/trailer/bundle.ts` serves its bundle.

## Conventions that matter

- **XSS:** JSX returns plain strings (children are NOT auto-escaped; attributes are). Any user-derived text needs `safe` on the element or `escapeHtml()`; `scripts/xss-scan.ts` (in `bun run check`) uses the TS checker and fails on a plain `string` child expression. HTML you build yourself must be typed `SafeHtml` (`import type { SafeHtml } from '@core/jsx'`).
- **Framework internals to know before editing `core/`:** `App` (`core/server.ts`) pipeline is `onRequest` hooks → route match (segment trie; static > `:param` > `*`) → `derive` → body parse (non-GET only; json/urlencoded/multipart/text) → schema validation (`params/query/headers/body`, failures throw `ValidationError`) → `beforeHandle` (guards) → handler → `onAfterHandle` → `toResponse` (string→html/text, object→JSON, async generator→SSE, `status()`, `Response` passthrough; `set.headers` and Set-Cookie are merged without overriding headers the Response already has) → `onResponse`. Errors thrown anywhere reach `onError` with a `code` (`NOT_FOUND`, `VALIDATION`, `PARSE`, `INVALID_COOKIE_SIGNATURE`, else 500). Plugins are plain functions `(app) => app.onRequest(...)`. Signed cookies are listed in `new App({ cookie: { signed } })` and verified on first `ctx.cookie` access. `t` in `core/schema.ts` strips undeclared object keys and coerces only `Numeric`/`Boolean`.
- **Performance rules (measured; don't regress):** `App.handle` returns a `Response` *synchronously* when no hook/handler returns a Promise (`runReq → runDerive → validate → runBefore → respond`, each stage chains `.then` only when it meets a Promise) — keep hooks/guards/derive sync unless they truly await, and never make `handle` `async`. Every response header costs ~1µs over HTTP, so headers are built in one `new Response(body, { headers })` call (`App.build`) and security headers are added only to HTML (`htmlSecurityHeaders`); don't add per-request headers casually. Per-request work that is not always needed goes in `app.lazy(name, factory)` (e.g. `ctx.session`), not `derive`. Static routes resolve via the `exact` Map before the trie. JSX string output is a rope: the first `startsWith`/`charCodeAt` flattens it, so don't scan big HTML strings repeatedly. Static components with stable output use `memo()` from `@core/jsx` (production only). The request logger (`core/logger.ts`) batches and rate-limits output — never `console.log` per request. `warmStatic()` pre-compresses `/public` at boot in production (brotli 11 on first request took >1s). Profile with `bun --cpu-prof`; micro-benchmark with `app.handle()` in a loop (see `src/lib/bench.ts`).
- **More perf notes:** `respond()` (`core/http-cache.ts`) builds the full header set (incl. HTML security headers and `server-timing`) in one object and registers the Response in `complete` (`core/server.ts`) so `App.passthrough` doesn't touch headers again — cache-hit and static handlers must stay non-`async` (return the Response directly; only misses return Promises). Uncached text responses ≥1 KB are gzipped at level 1 when `compress` is on (default in production, `COMPRESS=0` disables); `gzipCached` memoizes by body string so identical pages cost ~free. Measured and rejected: `Bun.serve({ routes })` static Responses gave no gain over a `fetch` handler returning a prebuilt Response (varying `Accept-Encoding` also rules them out). `SERVER_TIMING=0` drops the Server-Timing header.
- **Infra modules (all opt-in, `core/`):** `lb.ts` (+ `scripts/lb.ts` supervisor: spawns workers on PORT+1.., restarts crashed ones with backoff, IPC `'shutdown'` for graceful stop), `health.ts`, `ratelimit.ts` (sliding window, per-process), `cors.ts`, `jwt.ts` (HS256 only), `metrics.ts` (route label = `ctx.route` pattern), `jobs.ts` (SQLite queue; cron enqueues with `uniqueKey` per minute so multi-process is exactly-once), `resilience.ts`, `config.ts`. `createApp()` enables them from env (`RATE_LIMIT`, `CORS_ORIGINS`, `METRICS`, `TRUST_PROXY`). `App` tracks `inflight`/`draining`; `index.tsx` wires SIGINT/SIGTERM/IPC to `app.shutdown()`. SQLite pragmas: `busy_timeout` must come before `journal_mode` (workers start simultaneously). In tests use `app.listen({ port: 0 })` for real servers.
- **Feature installer (`bun run setup`, `scripts/setup.ts` + `scripts/setup/{lib,prompt}.ts`, templates in `features/`):** features are copied from `features/<id>/files/**` into the project root (manifest `feature.json`: `requires`, `nav`, `env`, `gitignore`, `notes`); presets in `features/presets.json`; `examples` is a *builtin* feature whose unselecting deletes its `remove[]` paths and overlays `features/_blank/files/**` (blank home page, empty `src/lib/db.ts`/`examples.ts`, `tests/smoke.test.ts`) — only on the first run. State lives in `.kitsune.json`; the web menu is generated into `src/lib/nav.gen.ts` (`Nav.tsx` reads it — never hardcode links there). `bunfig.toml` sets `[test] root = "./tests"` so `features/**/tests` templates are NOT run in the template repo. Features: `auth` (argon2id, session, JWT, guards `requireLogin/requireRole/requireApi` in `src/lib/guards.ts`), `admin`, `cms` (own markdown renderer: escape first, URL allowlist), `uploads` (magic-byte sniffing, random ids), `contact` (honeypot + signed timestamp + per-IP limit). `_guard.ts` stacks from parent folders, so different roles under `/admin` live in sibling folders (`admin/(dash)` = admin only, `admin/cms` = editor+). **Before shipping installer/feature changes, verify every preset in a temp copy** (copy repo, junction `node_modules`, `bun scripts/setup.ts --preset X --yes`, then `check-routes`, `tsc`, `xss-scan`, `bun test`) — all five presets must pass.
- **Project creator (`bun run create <dir>`, `scripts/create.ts`; packaged by `bun run pack:create` → `dist/create-kitsune/` = bundled `cli.js` + `template/`):** copies the repo file-by-file (`shouldCopy` excludes node_modules, .git, dist, *.sqlite, uploads, .env, .kitsune.json and the creator's own files `scripts/create.ts`, `scripts/pack-create.ts`, `tests/create.test.ts`), rewrites package.json (name, `private`, drops `bun-create`/create scripts), runs `scripts/setup.ts` in the new dir, `bun install`, `git init`, moves the old README to `docs/FRAMEWORK.md`. `package.json` `bun-create.postinstall` (`bun run setup --auto`) supports plain `bun create <repo|path>`. Don't use `cpSync` for the template copy (it refuses dest-inside-src). Verify installer/creator changes by scaffolding every preset through `create.ts` and running check + tests in each. Publishing to npm/GitHub is the owner's action — never publish from here.
- `data.sqlite*`, `dist/`, `core/reload.gen.ts` are gitignored artifacts.
